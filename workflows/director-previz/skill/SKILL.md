# 3D 导演台预演（director-previz）

## 这条工作流产出什么

`分镜与场景需求（文本）+ 全景氛围参考 → 3D 导演台（搭景 / 摆机位 / 截站位图）→ 选站位图 → 预演成片`

产物是两样，别混为一谈：

| 产物 | 是什么 |
|---|---|
| 导演台资产 | 一块**本地 3D 舞台**：全景背景球 + 你摆的几何体 + 机位 + 截图。构图与景别在这里被**手动定死** |
| 站位图 | 从机位渲染出来的静帧（宽 720 的降采样 JPG，供构图确认用） |
| 预演成片 | 由**视频模型**按"这张站位图 + 文本需求"生成的视频，不是 3D 渲染动画 |

## 什么时候用 / 什么时候别用

- 用：实拍/生成前的镜头预演、机位与景别推演、场景比例与构图确认、给分镜一个空间依据。
- 别用：要**成片级 3D 资产**（模型文件本身）→ `game3d-asset`（游戏3D资产）。
- 别用：要**可环视的空间世界 / 沉浸式环境** → `world-model`（世界模型，Marble 世界 → 导出网格）。
- 别用：只要**一段视频**、不需要空间依据 → `storyboard-video`（分镜出片）或 `game-ua-video`。
- 别用：要**多镜头叙事串起来**的片子 → `short-drama` / `short-drama9`。

## 上游输入怎么给

1. **分镜与场景需求**写进 `play.script` 节点（「分镜与场景需求」）的 `text`：场景氛围、镜头景别、构图意图。这条文本同时喂给全景图节点和预演成片节点（`brief:out` 有两条边）。
2. **全景氛围参考**由 `asset.image` 节点（「全景氛围参考」）生成，`generateInstruction` 已写好"360 全景氛围图，透视与光线方向明确"。
   - 用户已有全景图？直接在项目里引用它接到 `in-panorama`，不必再生成一张。
   - ⚠️ **全景必须是 2:1 等距柱状投影（equirectangular）**。导演台是把这张图贴到一个球内壁当背景，不做任何投影校正：非 2:1 的图会被拉伸变形，上下极点也会拧。所以给全景节点加 `generateAspectRatio: "2:1"`，或套用应用生成面板里那个「720 全景」指令预设（它明确要求 2:1、2048×1024 或 4096×2048）。
   - ⚠️ **不要用 `workflow_use_installed` 的 `generateAspectRatio` 统一宽高比**：那个参数会**覆盖**计划里所有 `asset.image` / `asset.video` 节点的比例，包括全景图节点 —— 传了 `16:9` 之类就会把全景图做成非 2:1，导演台背景随即变形。正确做法是先落图，再单独 `graph_edit` 给需要竖版/横版的节点（`asset.video` 预演成片）设比例。
3. **导演台不需要 3D 模型**：`asset.motion` 的 `in-model` 口可以空着，模板里也没连。用户没有模型是正常情况。
4. 想让全景图**永远不要因上游重跑而被换掉**？目前上游一变就重载背景，没有"锁背景"开关 —— 要固定就先把上游图跑好再进导演台。

## 关键约束与顺序（为什么）

- **连线是固化的四条**：`pano:out → motion:in-panorama`、`motion:out-shots → select:in`、`select:out → video:in-image`，外加 `brief:out → video:in-text`。
- **世界/模型不能替代站位图**：`asset.motion` 的出口是 `out-shots`（类型 `images`，复数）与 `out-actions`（`videos`）。`image.select` 的 `in` 口正好吃复数图片、`out` 口出单图。**不要把 `asset.motion` 直接连到 `asset.video:in-image`** —— 端口类型不兼容（多图 vs 单图），会被拒绝。
- **导演台必须人工介入**，这是本工作流的核心：全景背景不会自己搭出景，机位不会自己摆，**站位图不会自动产生**。执行顺序是：
  1. 跑「全景氛围参考」；
  2. 双击「导演台预演」进入舞台 —— 有 `in-panorama` 上游时背景球会自动加载这张图；
  3. 用基础几何体把空间关系搭出来（可用图元：`box` / `sphere` / `capsule` / `cylinder` / `cone` / `pyramid` / `prism` / `plane` / `quad` / `disc` / `ring` / `torus` / `tube` / `arch` / `pointedArch` / `cross` / `wedge` / `hemisphere` / `icosphere` / `octahedron` / `tetrahedron`），摆机位、调景别（画幅比例可选）；
  4. **截站位图**（舞台上有截图动作，截完会打开站位/动作面板）。截图以 720 宽渲染并压成 JPEG，最多保留 24 张，超出丢最旧；
  5. 回到图上跑「选站位图」和「预演成片」。
- **`image.select` 默认取第一张 = 最早截的那张**（`selectedImageId` 为空时回退 `items[0]`）。所以要么把想要的构图**先截**，要么明确在「选站位图」里选好。不要以为它会取最新一张 —— 那是图片/视频生成节点 `out` 口的行为，不是 select 的行为。
- **没截图就往下跑不会报错，但会产出一张没有构图依据的图**：导演台的 `out-shots` 列表为空时会**回退到舞台预览图**（`previewDataUrl` / `previewRelativePath`），既没有截图也没有预览图时输出空图。所以先确认站位图列表非空，再跑下游。
- **预演成片是"按站位图 + 文本需求生成的视频"**，不是 3D 渲染。默认把站位图当**参考图**（帧模式 `none`）；想让成片严格从这张构图起手，可把视频节点的帧模式切成 `first`，此时节点会动态长出 `in-first-frame` 单图口，把「选站位图」接到那个口上（帧模式一旦不是 `none`，`in-image` 的参考图会被剔除，两类参考互斥）。不要把它说成"精确的 3D 动画"。

## 常见追问怎么答

- **"能不能让人物在里面走 / 做动作"**：舞台支持摆位与机位，动作视频走 `out-actions` 口。本工作流的模板只用了 `out-shots`，没有接动作输出；要动作成片需要自己接 `out-actions`。
- **"站位图能出 4K 吗"**：不能。截图固定按 720 宽渲染，是**预演画质**。要高清关键帧就在站位图后接图片放大/重绘那类节点。
- **"能一次出多机位的成片吗"**：不能。`image.select` 出的是**一张**；多机位要多次选图、多次生成，或改用 `short-drama` 的流水线。
- **"地板/墙面能自动识别出来吗"**：不能。导演台不会从全景图里解析几何结构 —— 空间关系是**你手动摆几何体摆出来的**。
- **"能导入我的 GLB 模型当场景吗"**：`in-model` 口是为此准备的，但本工作流**没有连**。要走模型路线用 `game3d-asset`，或让用户自己把模型接进 `in-model`。
- **"为什么导演台里没东西"**：空舞台是正常的，需要手动搭景 + 摆机位；全景只是背景。

## 操作建议

1. 先确认用户要的是**构图预演**，而不是成品动画 —— 后者要的是视频工作流。这一条说清楚能省掉一整轮返工。
2. 全景图务必按 2:1 生成或用现成的等距柱状全景图，否则导演台里的背景会歪。
3. 落图后先只跑「全景氛围参考」，把导演台交给用户搭景摆机位 —— **这一步 agent 代替不了**，不要假装跑一遍 `task_run` 就等于预演完成。
4. 用户截好站位图后再跑「选站位图」→「预演成片」。视频是远程任务，用 `task_status` 轮询。

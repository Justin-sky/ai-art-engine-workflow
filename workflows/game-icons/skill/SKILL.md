# 游戏图标包（game-icons）

## 这条工作流产出什么

三条**同构的并行轨道**（技能 / 道具 / 状态），每条都是：

```
画风主题 ┐
         ├→ ·整版（3×3 九宫格整版表） ─┬→ ·切格（目检用）
名单     ┘                             └→ ·打包（交付）
名单 ───────────────────────────────────→ ·打包
```

产物是**三包透明底 PNG 图标**：

- `Assets/IconPacks/skill`、`Assets/IconPacks/item`、`Assets/IconPacks/status` 三个目录
  （由各打包节点的 `mediaOutputDir` 决定）；
- 每枚图标一个 PNG，文件名为名单那一行（非法文件名字符会被替换，空白折叠成下划线）；
- 统一方形画布、中心对齐、背景键控为透明；
- 同目录另有一份清单文本（节点以 `icons` 为 key 落盘，实际文件名为 `icons.txt`，
  同名已存在时变成 `icons 2.txt`，内容是 JSON：`grid` 行列、每枚的 `name` / `fileName` /
  `cellKey` / 尺寸 / 锚点，以及键控采样到的背景色）。**注意扩展名是 `.txt` 而内容是 JSON**，
  别当纯文本读。

## 什么时候用 / 什么时候别用

| 用户想要 | 用哪条 |
|---|---|
| 一**套**图标、按名单逐枚出图、要透明底 PNG 打包 | **本工作流 `game-icons`** |
| 游戏 UI 界面（背包 / 任务 / 公会屏），要策划案 → 界面拆分 → 逐屏出图 | `game-ui`（游戏UI界面） |
| 单个图标、只出一张图 | 别用整条工作流：一个 `asset.image` 节点就够，不必上宫格 |
| 3D 图标 / 模型展示 | `game3d-asset`（游戏3D资产） |
| 从一张已有整版图切格 / 抠底（不重新生成） | `image.gridSplit` + `image.iconPack` 两节点即可 |

**不要**答应「矢量图标」：这条链路出的是位图 PNG。要 SVG 走应用内 SVG 生成链路
（`svg.gen`），不是本工作流。

## 上游输入怎么给

装完工作流后用 `workflow_use_installed({ id: 'game-icons' })` 落盘，取回 `assetId`；
再 `graph_read({ assetId, includeParams: true })` 拿节点 id，然后 `graph_edit` 填参数。

| 要提供的东西 | 落到哪里 | 格式 |
|---|---|---|
| 技能图标名单 | `play.script`「技能图标名单」的 `params.text` | **一行一枚**，≤ 9 枚 |
| 道具图标名单 | `play.script`「道具图标名单」的 `params.text` | 同上 |
| 状态图标名单 | `play.script`「状态图标名单」的 `params.text` | 同上 |
| 画风主题句 | `play.script`「画风主题」的 `params.text` | 一句话；三条轨道共用 |
| 统一画风参考图 | 各「·整版」节点（`asset.image`）的 `styleImages`，配 `styleReferenceSubject: 'ui'` | 条目须带 `libraryId` 或 `data:` 开头的 `dataUrl` |

名单格式细节（`play.script` 就是纯文本，文本怎么解析由下游决定）：

- 换行分隔，**一行的顺序就是格位顺序**，row-major：第 1 枚 → `1-1`，第 3 枚 → `1-3`，
  第 4 枚 → `2-1`；缺省 `3×3` 时第 9 枚 → `3-3`；
- 空行忽略；以 `#` 或 `//` 开头的整行忽略（可用作注释）；
- 超过 9 行时**打包节点会直接报错**（`名单数 > rows×cols`），整版节点也会把多出来的
  强行挤进画面导致格位对不上 —— 每类先按 ≤ 9 收；
- 少于 9 枚是**推荐状态**：空着的格子留纯色底，打包时正好用它采样背景色。

**名单必须同时接给「·整版」和「·打包」。** 整版节点用名单决定画什么、按什么顺序；
打包节点用名单决定每格叫什么名字。plan 里已经是两路都接好的：

```
技能图标名单:out → 技能图标·整版:in-text
技能图标名单:out → 技能图标·打包:in-text
技能图标·整版:out → 技能图标·打包:in
技能图标·整版:out → 技能图标·切格:in
```

`play.script` 只有 `out` 一个口，可以扇出到多个下游；`image.iconPack` 有两个入口
（`in` 吃整版图、`in-text` 吃名单），**别把名单接到 `in`**。

## 关键约束与顺序

1. **三类必须用同一张风格参考图**，否则三包图标画风不统一 —— 这是这类资产最容易翻车的地方。
   参考图走 `styleImages` + `styleReferenceSubject: 'ui'`：风格图会作为**真实参考图**进模型请求
   （排在 `image[]` 前几张），提示词里再按位置写上「参考风格」字样，`'ui'` 语义是
   允许复刻参考图的界面语言。**只把风格写成文字没用**，参考图要真的给进 `styleImages`。
2. **整版表的九宫格一致性靠提示词约定，没有强制手段。** 模型可能把格位画偏、把主体画出格、
   或者多画一枚。所以流程里**先跑「·整版」，再跑一次「·切格」目检格位**，确认无误才打包。
   不要跳过目检直接交付。
3. **整版节点不画文字、不画网格线与外框**（指令里已明确要求）。这是刻意的：多了线框，
   打包的「内缩削边」会把图标边缘也削掉，键控也更容易误伤。
4. **改名单后「·整版」必须重跑。** 整版是一张生成图，名单只是它的输入提示词；
   改了名单却不重跑，打包就还是会从旧整版裁、并套用新名字 —— 名字与画面对不上。
   改名单**不影响**已落盘的旧 PNG，重跑打包会再出一批新文件。
5. **「·切格」节点不产出交付物**，它是单枚检查 / 精修的并行出口。它的 `selected` 为空时
   切出全部 `rows × cols` 格；只想看某一枚就把 `imageGridSplit.selected` 设成 `["2-3"]`。
   **不要**把交付指望在切格上 —— 透明化与统一画布只有打包节点做。
6. **透明底是「采样 + 色距键控」，不是抠图模型。** `keyColor: 'auto'` 的采样顺序是：
   名单未占满时采样**第一个空白格**中心区域 → 占满 9 枚时依次尝试采样**整版图外框色带**
   （上 → 下 → 左 → 右）。所以名单留空格时效果最稳。打包输出是「主体修剪后中心对齐到统一方形画布」。
7. **文件名来自名单**：名字里的 `\ / : * ? " < > |` 与控制字符会被替换成 `_`，空白折叠为 `_`。
   要改交付名就改名单那一行，然后重跑打包（重跑会再出一批新文件，不会覆盖旧的）。
8. **打包是纯本地像素处理，不调模型、不花钱**；三条轨道里只有「·整版」是生图节点。

## 参数与调参（细节见 `references/grid-and-pack.md`）

| 想改什么 | 参数 | 说明 |
|---|---|---|
| 网格行列 | `imageGridSplit.rows` / `.cols`、`iconPack.rows` / `.cols` | 两处都必须一致，范围 1–5；默认 3×3 |
| 统一输出尺寸 | `iconPack.canvasSize` | 1–2048 方形；`0` = 按本批主体最大外接框自动定边 |
| 边缘削边 | `iconPack.edgeInset` | `'auto'`（按格子尺寸约 1.5%，封顶 12px）或 0–64 的整数 |
| 键控模式 | `iconPack.keyColor` | `auto` / `black` / `white` / `none`（`none` = 不抠，原样打包） |
| 键控容差 | `iconPack.distance`（0–255，默认 40）、`iconPack.feather`（0–255，默认 34） | 残留底色 → 调大 `distance`；边缘发白/锯齿 → 调 `feather` |
| 输出目录 | 各打包节点的 `mediaOutputDir` | plan 已预设 `Assets/IconPacks/{skill,item,status}` |

**发光 / 半透明类图标（火焰、圣光、护盾）要小心**：色距键控会把与底色接近的浅色部分一起变透明。
这类图标建议改用 `keyColor: 'black'` 或 `none`，或者让整版用深色描边 + 明确主体。

## 常见追问怎么答

- **「某一枚不满意，能只重画这一枚吗？」** 能。用 `graph_icon_refine({ assetId, splitNodeId, cellKey, hint })`：
  `splitNodeId` 是那一类「·切格」节点的 id（`graph_read` 查），`cellKey` 形如 `2-3`，
  `hint` 写不满意的点；`repack` 默认 `true`，会用精修图顶替该格重出 PNG。
  它需要该资产的图编辑器处于关闭状态，且耗时较长（一次生图 + 一次打包）。
- **「能自动把我给的名单逐枚画准吗？」** 不能保证。整版是一张图，格位对齐是提示词约束出来的，
  所以要目检；对不上的格子用上面的精修回炉修。
- **「能出不透明 / 指定底色的图标吗？」** 把 `iconPack.keyColor` 设成 `none` 就是原样打包，
  但那样会连整版的底色一起带出来。
- **「能出 2K / 4K 大图图标吗？」** `canvasSize` 上限 2048。而且打包是**从整版裁切**，
  不是重绘放大 —— 想更清晰要么把整版 `generateResolution` 提高，要么单独放大某几枚。
- **「能出 SVG / 矢量图标吗？」** 不能，这条链路全是位图 PNG。
- **「三类一定要各 9 枚吗？」** 不用，少于 9 枚更好；**超过 9 枚会直接失败**。
  超过就先分两批（把 `rows`/`cols` 放到 3×3 以上也行，但上下限是 5×5 且要两处同步改）。
- **「清单文件叫什么？」** 节点以 `icons` 为 key 落盘，文件名 `icons.txt`；
  同名已存在时自动变成 `icons 2.txt`（PNG 同理：重名图标变 `火焰斩 2.png`），**内容是 JSON**。
- **「要多久？」** 只有三次生图（三条整版），其余全是本地像素处理；
  精修回炉另算一次生图。别把打包说成「要跑很久」。

## 操作建议

1. 先确认**三类各要哪些名字**、以及**有没有统一画风参考图** —— 这决定了成品能不能用。
2. 顺序：填三个名单 + 主题 → 跑三条「·整版」→ 跑「·切格」目检 → 跑三条「·打包」。
3. 报结果时按目录说清楚：`Assets/IconPacks/skill`、`/item`、`/status`，
   并提醒清单文件是 JSON 内容。
4. 名单改了就重跑对应整版 + 打包，两件都要做。

端口、参数表与错误对照见 `references/grid-and-pack.md`。

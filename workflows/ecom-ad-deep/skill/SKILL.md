# 电商带货（ecom-ad-deep）

## 这条工作流产出什么

`卖点文案 → 产品主视觉 / 使用场景图 → 广告变体矩阵（批量） → 图层分离（交付）`

产物是**成批的电商广告图**，不是视频：

1. **产品主视觉**：一张干净的电商英雄图；
2. **使用场景图**：一张真实使用场景图；
3. **广告变体矩阵**：按用户给的维度（机位角度 / 钩子文案 / 视觉风格…）做笛卡尔积展开，
   每格一张图 —— 这才是「deep」的部分，换来的是可投放对比的多版本素材；
4. **图层分离**：把主视觉拆成「底图 + 透明图层」的多张 PNG + 一张合成图，
   在图层编辑器里可继续调层级 / 位置并导出 PSD 或分层 PNG。

## 什么时候用 / 什么时候别用

| 用户想要 | 用哪条 |
|---|---|
| 多版本电商素材、要 A/B 对比、要拆层改详情页 | **本工作流 `ecom-ad-deep`** |
| 只要一条产品广告**短视频**（主视觉 + 场景 + 10 秒视频） | `product-ad`（产品广告） |
| 游戏买量素材（剧本 → 分镜 → 视频） | `game-ua-video`（游戏买量） |
| 已有素材、只想串成视频 | `storyboard-video`（分镜出片） |
| 只要有分层 PSD、不需要变体批量 | 别用整条工作流：`image.layerSplit` 单节点接上主视觉就够 |

**不要**把这条当成「出视频」的工作流推荐 —— plan 里没有任何 `asset.video` 节点。

## 上游输入怎么给

装完工作流后先用 `workflow_use_installed({ id: 'ecom-ad-deep' })` 落盘，返回 `assetId`；
再用 `graph_read({ assetId, includeParams: true })` 拿到各节点 id，然后 `graph_edit` 填参数。

| 要提供的东西 | 落到哪里 |
|---|---|
| 产品名、核心卖点、优惠信息、CTA | `play.script` 节点（标题「卖点文案」）的 `params.text` |
| 变体维度与取值 | `image.adVariants` 节点的 `params.adVariantMatrix`（见下） |
| 产品参考图（用户已有实拍图时） | 接进「产品主视觉」的 `in-image` 端口；或写该节点的 `characterRefs`（条目须带 `imageUrl`） |
| 出图模型、统一宽高比 | `workflow_use_installed` 的 `imageModel` / `generateAspectRatio`（后者只注入到 `asset.image` / `image.upscale` / `asset.video` 节点），不必逐节点写 |

**文案是自动拼进提示词的，不要重复写。** 「卖点文案 → 产品主视觉 / 使用场景图」走的是
`in-text` 端口：图片节点会把它**自动追加**到自己的 `generateInstruction` 之后
（除非该指令里用了 `@n` 提及语法）。所以：

- 用户给卖点时，写进 `play.script` 的 `text` 即可，**不要**再把同一段文字抄进
  `generateInstruction` —— 会重复两遍；
- 想给每个节点不同侧重，就改各自的 `generateInstruction`（主视觉已预设「干净背景」，
  场景图已预设「真实使用场景」）。

### 变体矩阵怎么写

`adVariantMatrix` 的关键字段（完整结构见 `references/ad-variants.md`）：

```json
{
  "product": "产品名 + 卖点描述（每格提示词的第一段，必填）",
  "aspectRatio": "1:1",
  "dimensions": [
    { "id": "d-angle", "label": "机位角度", "values": ["正面平视", "45°侧面", "俯拍"] },
    { "id": "d-hook",  "label": "钩子文案", "values": ["限时五折", "买一送一"] }
  ],
  "cells": []
}
```

- `product` + `dimensions` 会被**笛卡尔积展开**：上例 3 × 2 = **6 个单元格 → 6 次生图**。
  维度值是「直接拼进提示词的片段」，不是枚举关键字，随便写自然语言。
- `cells` 留空数组就行，执行时会展开并回填；手写 `cells` 反而容易把 `id`
  （形如 `cell-d-angle=正面平视|d-hook=限时五折`）写错。
- `dimension.id` 只要求非空字符串、在每个矩阵内**唯一**（建议 `d-` 前缀），
  `label` 是拼进提示词的字段名（如「机位角度：45°侧面」）。
- **数量要跟用户确认**：维度和取值越多，出图张数与等待时间按乘积增长。
  别自作主张给 4 个维度 —— 4 个维度各 3 取值就是 81 张图。
- 应用界面的变体编辑器里有「通用 / 行业 / 促销」预设维度（美妆、电子、食品、服饰…）
  可直接套用；**MCP 没有套用预设的工具**，走 agent 这条路要自己把维度写全。

## 关键约束与顺序

1. **主视觉必须先跑出来**：`adVariants` 与 `layerSplit` 都从主视觉节点的 `out` 取图
   （`out` = 该节点图库里当前选中的**那一张**）。变体会把它作为**参考图**注入每个单元格、
   保证产品一致（若确实收到多张，只用第一张）。所以主视觉没有产物时，变体矩阵会直接报没有输入。
2. **`out` 是单数口、`out-all` 是复数口**：想换参考图就在主视觉节点的图库里改选中那一张，
   不要试图把 `out-all` 接到 `adVariants.in` / `layerSplit.in` —— 复数类型与单数入口不兼容，
   只有 `image.select` 一类节点才吃 `out-all`。
3. **`image.layerSplit` 走的是上游的图层分解能力**（Seedream 系列的 `layer_decomposition`）。
   换到不支持该能力的图片模型上，拆层会失败或返回不了图层；这条链路优先用支持拆层的模型。
4. **`imageLayerSplit.prompt` 参与「源图指纹」**：改了 prompt 或 `resolution`
   会判定为源图变化并**重新调一次拆层 API**（额外计费）。只调层级 / 位置不会重新拆层。
5. **`image.layerSplit` 节点的 PSD 导出不在节点里**：执行只产出「图层 PNG + 合成图」。
   PSD 是**用户在应用里双击图层分离节点、打开图层编辑器后点「导出 PSD」**得到的
   （那是本机保存对话框）。**agent 没有导出 PSD 的 MCP 工具**，不要承诺「我帮你导出 PSD」，
   应回答「跑完节点后由你在图层编辑器里点导出」。
6. **`使用说明` 是 `note.text` 节点**：它只承载给用户看的说明，**没有端口、不参与执行**。
   不要试图把它连到任何地方，也不要指望改它能改变生成结果。
7. **使用场景图目前没有下游**（plan 里它只接收文案）。它是给人用的备用素材；
   跑整图时它会一起生成，这是预期行为，不是断链。

## 常见追问怎么答

- **「能出短视频吗？」** 本工作流不能。要视频用 `product-ad`（产品广告，自带
  `asset.video` 节点）；或在当前图里用 `graph_edit` 的 `node_upsert` 加一个
  `asset.video` 节点并自行连线 —— 但那是改造，不是这条工作流的能力。
- **「能自动写卖点文案吗？」** 不能。`play.script` 只存文本，不做生成；
  文案要用户给，或先用文本模型单独写好再粘进去。
- **「能出竖版 9:16 吗？」** 可以。用 `workflow_use_installed` 的 `generateAspectRatio: '9:16'`
  只覆盖 `asset.image` / `image.upscale` / `asset.video` 三类节点（主视觉、场景图会变竖版），
  **不覆盖变体矩阵**；变体那一批要竖版必须在 `adVariantMatrix.aspectRatio` 里写，两处都要写才一致。
- **「变体图能不能只保留入选的？」** 可以看，但要在应用内的变体矩阵编辑器（双击节点）里
  用「入选 / 淘汰」标记、在对比视图里筛。**MCP 没有变体标记工具**，agent 只能读回结果。
- **「要多久？」** 变体是**逐格串行生图**（每格一次图片 API 调用），张数越多越慢；
  报进度时按「张数 × 单张耗时」估，不要承诺几十秒内出几十张。
- **「能指定产品一定要和实拍图一致吗？」** 变体只会拿主视觉 `out`（当前选中那一张）当参考图。
  要锁真实产品，先把用户实拍图接进主视觉、把它选为当前图，再跑变体。

## 操作建议

1. 先问清**卖点文案**与**要几个变体方向**，这两样决定绝大部分产出。
2. 生成顺序：主视觉 → （场景图）→ 变体矩阵 → 图层分离。
   图层分离可以独立于变体先跑，用来先确认分层质量。
3. 变体张数多时，先只跑一个维度、数量小的一批给用户看风格，确认后再放开维度。
4. 图层分离产出后，提醒用户「双击节点 → 图层编辑器 → 导出 PSD / 分层 PNG」。

参数速查见 `references/ad-variants.md`。
